# Лабораторна робота №7

**Тема:** Multi-module Maven  
**Гілка проєкту:** `lab7`  
**Репозиторій:** [Java_3, гілка lab7](https://github.com/YevhenRybachuk/Java_3/tree/lab7)

Проєкт переведено на багатомодульну структуру Maven. Кореневий POM об’єднує незалежні сервіси в один reactor build, а кожен сервіс має власний запуск, конфігурацію, порт, тести та Dockerfile.

## 1. Батьківський POM і спільна збірка

Кореневий `pom.xml` має `packaging` зі значенням `pom` і містить обидва модулі: `subscription-service` та `reporting-service`. Батьківський POM кожного модуля посилається на кореневий POM.

Спільну тестову залежність `spring-boot-starter-test` оголошено в кореневому POM. Специфічні runtime-залежності та Spring Boot Maven Plugin розміщені у POM відповідного сервісу.

## 2. Сервіс підписок (`subscription-service`)

Цей модуль містить наявну функціональність керування підписками, REST API та вебінтерфейс. Головний клас — `Lab1Application`; конфігурація розташована у власному `application.yml`, порт сервісу — `8080`.

Модуль має окремий набір тестів і Dockerfile. Параметри підключення до MySQL можна передати через `DB_URL`, `DB_USERNAME` і `DB_PASSWORD`; типове локальне підключення використовує `localhost:3307`.

## 3. Сервіс звітів (`reporting-service`)

Звітний сервіс окремо запускається з `ReportingApplication` на порту `8082` та надає endpoint `/reports/subscriptions/summary`. Він отримує список підписок через API сервісу підписок, передає JWT запиту й обчислює кількість підписок і суму їхньої вартості.

Сервіс має власну конфігурацію OAuth2 resource server, адресу сервісу підписок можна задати через `SUBSCRIPTION_SERVICE_URL`, адресу issuer — через `KEYCLOAK_ISSUER_URI`. Він не підключається напряму до бази підписок і не має Maven-залежності на `subscription-service`. Для сервісу створено окремі тест і Dockerfile.

## 4. Незалежність модулів і перевірка

Модулі не залежать один від одного на рівні Maven. Обмін даними між сервісами відбувається через HTTP API; спільний модуль `common` не потрібен.

Перевірки виконано з кореневої директорії:

- `mvn verify` — успішно; тести обох сервісів пройшли.
- `mvn -pl subscription-service dependency:tree` — успішно.
- `mvn -pl reporting-service dependency:tree` — успішно.

Кожен Dockerfile збирає окремий виконуваний образ сервісу.
